How Signups Work

There are three kinds of signup sheet — raids, teams, and plain events — all built and closed the same way.

Reacting to sign up

Raids use three custom role emoji; teams and events use a single join reaction:

🛡️ Tank ✨ Healer ⚔️ DPS ✅ Join (teams & events)
  • Reacting adds you to the sheet in the order you signed up.
  • On a raid, reacting with a different role automatically removes your old reaction and moves you over — you can only hold one role at a time.
  • Removing your reaction removes you from the sheet entirely.
  • Signups stay open to everyone regardless of size — caps and grouping are only applied when the sheet is closed.

Party formation — raids

When a raid is closed, signups are bin-packed into parties by role, first-come-first-served, filling one party completely for a role before spilling into the next. Parties are always 2 Tank / 2 Healer / 4 DPS.

Half-empty final parties are fine — a new party only opens once the previous one is full for that role.

ℹ️

The party size you pick at creation (Small Party, Full Party, Alliance Raid) is currently just a label shown on the signup sheet — it doesn't change the 2/2/4 caps used when the raid is closed.

Team formation — teams

Closing a team sheet splits signups by join order. Give it a team size when you create it and teams fill up sequentially, one at a time (a half-empty last team is fine). Leave size out and it splits everyone evenly into exactly 2 teams, round-robin.

Attendance — events

Events don't get grouped at all. Closing one just posts the full list of everyone who reacted — a simple "who's coming" roster.

Setting a location

When creating a raid, team, or event you can optionally say where it's happening — pick a voice channel, or type a plain-text location. You only need one of the two, not both — if a voice channel is set, the location text is ignored.

  • Leave both blank and, in the main Initiative server, the bot falls back to a default voice channel automatically.
  • If you also set a time, the bot creates a matching native Discord Scheduled Event — same title, time, image, and location — with a link back to the signup message, so it shows up on everyone's Discord calendar too.
  • No scheduled event is created if you didn't set a time (Discord requires a start time for those), and if the bot doesn't have the "Create Events" permission it just skips this step quietly — your signup sheet still gets posted either way.

Finding an event by ID

Every id option — in /close, /delete, and the update commands — autocompletes. Start typing the event's title and Discord will suggest matching open events as "#ID — Title" as you type. You can still type the raw number directly if you already know it.

Every raid, team, and event is also tied to the Discord server it was created in, so these lookups can only ever find one from that same server — even if you type a raw ID that happens to belong to a raid in a different server.

Descriptions

Every create and update command has an optional description field — plain text shown right in the signup embed. Handy for loot rules, a strategy note, or anything else worth pinning above the roster.

💡

Discord's slash-command text fields won't let you press Enter for a line break — type \n wherever you want one instead, and the bot converts it to a real line break in the embed.

Listing & deleting

/events DMs you a list of everything still open in the server — every raid, team, and event with its ID, type, scheduled time, and a link straight to the signup message. Handy when you've lost track of what's running.

/held-events is the wider view — it replies right in the channel (no DM) with everything that's ever been posted in this server, open and closed, split into two lists so you can see what already wrapped up too.

/close is how you normally finish something — it locks signups and posts the results. /delete is different: it's for removing a signup sheet entirely, open or closed.

⚠️

/delete is permanent. It deletes the signup message, cancels the linked Discord calendar event, and erases all of that sheet's signups — there's no confirmation prompt and no undo. Reach for /close to finish something properly; only use /delete to clean up a mistake.

Timezone-aware scheduling

Raid, team, and event times are all entered the same way: a date, a time, and the organizer's own timezone. The bot converts that to a single point in time and renders it with Discord's native timestamp formatting, so every member sees the time and countdown in their own local time automatically — no manual conversion needed. Timezones are fixed UTC offsets rather than DST-aware, so it's worth double-checking times that straddle a DST switchover.

💡
